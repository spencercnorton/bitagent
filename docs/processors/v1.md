# Processor protocol v1

Canonical wire definitions: [`processorapi/v1/types.go`](../../processorapi/v1/types.go).
Contract string: `bitagent.processor.v1`. JSON is UTF-8, finite numbers only.
Unknown properties, duplicate object keys, trailing JSON, oversized bodies and
unsupported versions are rejected. Job/result bindings must match exactly.
No particular model, framework, host, credential provider or metadata supplier
is required. Non-model processors use `model_version` and `artifact_digest`
`none`; model artifacts use a lowercase 64-character SHA-256 digest.

## Service surface

- `GET /v1/manifest`: `Manifest`, immutable identity, capabilities, JSON Schema
  draft-07 configuration schema and informational qualification. A service must
  change its identity when its runtime, model artifact or policy changes.
- `GET /v1/status`: `ServiceStatus`. Readiness does not certify correctness.
- `POST /v1/process`: one `Job`, one `Result`, synchronous and deadline bounded.
  Return 429/503 for overload/unavailability. No independent queue or callbacks.
  Repeated job IDs must not cause irreversible effects. Cache identity includes
  the complete binding and configuration; conflicting reuse is an error.
- Request cancellation closes the request context. The service must abandon
  work by `deadline` even if it cannot observe disconnect. Late results cannot
  be applied. HTTP redirects are forbidden. Bearer authentication is optional
  on isolated test networks and configured separately from model credentials.

The core owns durable jobs, retries, leases, cancellation and acknowledgement.
A plugin may maintain a bounded result cache; it must not claim durable queue
ownership. Model/provider credentials belong only in the plugin service.
Services run under an external supervisor with CPU, RAM, PID, disk and network
limits. The reference Compose example demonstrates that boundary.

## Ordering and authority

Core discovery, persistence, deterministic parsing and normal matching happen
first. Optional stages are `classify`, `extract`, `match`, `language`, `policy`,
`embed`, in that order. Within a stage, order by configured priority ascending,
then processor ID ascending. The plan and all versions are frozen per pipeline
revision. Core facts win; the first valid proposal for an unset field wins.
Every later step receives prior results. Outcome ordering is not arrival order.

A `completed` result proposes facts; it does not authorize publication.
`abstained` means no opinion. `deferred` means temporary capacity/evidence delay.
`failed` means technical failure. `excluded` is a proposed, reversible policy
restriction. `unmatched` means a completed unsuccessful match, only valid for
the match stage after a complete search; provider outage or missing evidence
cannot produce it. No outcome permits a plugin to delete or blacklist a hash.

Core rechecks input revision, active registry generation, policy, privacy,
manual/canonical authority and field validity in the application transaction.
Type alone grants no identity. Match proposals must select a core-supplied
candidate and satisfy independent source-title/year/type/episode constraints.
Extraction, language claims and embeddings remain attributed proposals;
metadata claims are not verified physical audio or release identity.

Shadow plugins never alter catalogue eligibility. A qualification label never grants authority. An operator can
explicitly enable supported application for a registered version. Qualification
reported by the plugin is informational and never changes that mode. A plugin
failure does not make a torrent junk, remove an existing exclusion or make an
ineligible torrent eligible. Existing eligible results remain served.

## Identity and upgrade

`job_id`, `input_revision`, `pipeline_revision` and `configuration_digest` are
opaque lowercase SHA-256 values generated by core. Echo them unchanged with
`processor`, `stage` and `contract`. Do not reconstruct core digests from JSON.
The input digest binds raw metadata and core evidence, including file evidence.
A runtime/model/policy/configuration/registry change creates a new plan version.

Warm a replacement at a separate endpoint. Core validates manifest, status and
configuration before compare-and-swap activation. Old jobs cannot apply after
activation. Drain pauses new admission and waits for bounded leases; removal
cancels outstanding jobs. Rollback registers the previous immutable identity
under a fresh generation. Already applied facts and their provenance persist;
rollback changes future processing and never erases catalogue history.

## Bounds and failure

Core imposes hard request/result byte caps, file/candidate/embedding limits,
concurrency, attempt deadlines, per-step retry ceilings, queue capacity and
retention. Plugin-reported retry delay is clamped. Terminal failure of one
processor does not stop later independent processors or the core pipeline.
Lease generations reject duplicate/late delivery after crash recovery.
Malformed or incompatible results are technical failures, never abstentions.

## Normal processing and exact semantic inputs

`deterministic.processing_outcome` records `completed`, `deferred`, or
`not_attempted` for the normal core pipeline on the raw metadata revision and
core policy. It is distinct from `matching_outcome`. Unknown types can finish
normal processing without an applicable matcher, so completed processing plus
not_attempted matching is honest input to a type processor. Only an actual
complete normal search on the corresponding catalogue row can certify
completed_unmatched. Neither missing receipts nor provider errors certify it.

The request's nullable `file_count` and `extension` are stored source fields.
Do not substitute the transmitted list length for file_count: a bounded inventory
may be incomplete. Files are deterministically sorted and files_complete is
explicit. Matching candidates and preceding results are frozen at each step's
first preparation. The step ID includes that complete semantic input revision;
retries reuse it and change only deadline. Concurrent candidate changes cannot
reuse an ID with a different request.

A failed/deferred apply step withholds new catalogue enrichment from the entire
optional pipeline. Other processors may still run and record evidence. Explicit
restrictions remain restriction-only. Abstention supplies no authority; a valid
independent proposal still must pass core validation. Supported type enrichment
fills only unknown type and deterministic release fields. Existing types,
identities, hints and independent privacy/manual authority win. Extraction,
language and vector outputs remain attributed data for subsequent processors,
not direct physical/identity claims or a new search index.

See `v1.schema.json` for portable structural definitions, `fixtures/` for JSON
examples, and `processorapi/v1/validate.go` for normative semantic constraints.
Regenerate structural definitions/examples with `go run ./tools/processor-contract`.
Schema validation alone is insufficient: binding equality, offered-candidate
membership, outcome/proposal consistency and bounded numeric values also matter.

`telemetry.observed_at` is the time of the computation that produced the reported
resource measurement. Status polls do not refresh it. Missing values/timestamps
remain unavailable. `instance_id` and `started_at` distinguish service restarts;
processor/model/policy/artifact identity remains immutable for that instance.
